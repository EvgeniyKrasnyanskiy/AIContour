# Changelog

Все заметные изменения в проекте ASS (Auto Segmentation System) фиксируются в данном файле.
Формат соответствует [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).

## [Unreleased]
- **Облегченный пакет воркера и автоматическое развертывание в 1 клик:**
  - В диалоге создания воркера `CreateWorkerDialog` по умолчанию отключена упаковка тяжелого 5 ГБ `venv`, что сократило размер архива воркера до компактного вида (с возможностью опциональной упаковки весов нейросети `totalseg_home/` ~1.3 ГБ для оффлайн-работы).
  - В пакет воркера включено обязательное сохранение всех пресетов органов (`config/presets/`) и конфигураций (`colors.json`, `structure_names.json` и др.), исключающее ошибку отсутствия пресета (`thoracic_oar` и др.).
  - Скрипт `run_worker.bat` переработан в режим 1-click: при первом запуске на целевой машине он автоматически вызывает `setup_worker.bat`, проверяет наличие Python 3.10/3.11, создает `venv` и устанавливает зависимости через `pip install -r requirements.txt`.
  - Во все bat-скрипты воркера (`run_worker.bat`, `setup_worker.bat`, `run_worker_no_console.bat`) добавлена очистка переменных прокси (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY=*`), предотвращающая сбои связи с сервером из-за локальных системных прокси.
- **Отключение проверки обновлений на GitHub (только сервер ASS):**
  - Из потока `UpdateCheckerThread` полностью удалены внешние fallback-запросы к GitHub Releases API.
  - Поиск обновлений в клиенте теперь выполняется исключительно через локальный сервер ASS (`/api/updates/client/info`), гарантируя полную автономность и корректную работу в изолированных медицинских сетях без доступа в интернет.
  - Из интерфейса и диалогов клиента исключены упоминания GitHub и внешние гиперссылки.
- **Устранение консольного окна клиента и подавление ложного варнинга подключения при старте:**
  - В `build_clientPyQT6.py` сборка клиента переведена на режим `--windowed` (вместо `--console`), что устраняет появление окна командной строки Windows при запуске `ASS_Client.exe`.
  - В шаблон запуска `run_client.bat` добавлена инициализация системного пути `%SystemRoot%\System32` и запуск через `start "" "%~dp0ASS_Client.exe"`.
  - В `client_app.py` заблокирована отправка сигналов комбобокса палитры цветов во время `load_settings()` и добавлен флаг готовности интерфейса `_is_initialized`, что исключило отправку запросов на несуществующий сервер и предупреждение `[WinError 10061]` в логах при запуске.
- **Исправление создания пакетов воркеров, фонового режима и автономного запуска:**
  - **Потокобезопасное обновление таблицы кластера (`ClusterStatusSignaler`):** неработающий вызов `QTimer.singleShot` из фонового потока заменен на специализированный сигнал `pyqtSignal(dict)`. Таблица узлов и метрики ОЗУ кластера теперь гарантированно отрисовываются и обновляются в реальном времени.
  - **Удаленное включение и отключение воркеров в 1 клик:** в таблицу кластера добавлена колонка «Управление» с кнопками `⏸️ Отключить` / `▶️ Включить`, позволяющая администратору мгновенно исключать воркер из пула задач (статус `DISABLED`) без остановки службы.
  - **Скрытый запуск, проверка статуса и автозагрузка воркеров (`run_worker_no_console.bat`, `status_worker.bat`, `stop_worker.bat`, `add_to_startup.bat`, `remove_from_startup.bat`):**
    - В комплект воркера добавлены скрипты для фонового запуска без консольного окна через `pythonw.exe` и быстрого добавления/удаления из папки автозагрузки Windows (`shell:startup`).
    - Добавлены утилиты `status_worker.bat` (проверка активности процесса `pythonw.exe` и просмотр хвоста лога в 1 клик) и `stop_worker.bat` (остановка службы в 1 клик).
    - Все bat-скрипты переведены на строгий ASCII-формат для предотвращения сбоев разбора кириллицы в командной строке `cmd.exe` русской локализации Windows. Удаление ярлыка в `remove_from_startup.bat` переведено на маску `ASS_Compute_Worker*.lnk`.
  - **Исправление исключений в ZipPackageThread (сохранение `unittest`, `pydicom.examples` и подмодулей):** заменена грубая проверка подстрок `ex in d` и `ex in f` на строгое сопоставление имен, а из фильтров `Lib` и `site-packages` удалены паттерны `test`, `tests`, `examples`. Устранены ошибки `ModuleNotFoundError: No module named 'unittest'` и `ModuleNotFoundError: No module named 'pydicom.examples'`.
  - **Включение модулей движка в пакет воркера (`contour_engine.py`, `config.py`, `version.txt`):** в список упаковываемых корневых файлов в `server_app.py` добавлены `contour_engine.py`, `config.py` и `version.txt`. Устранена ошибка `ModuleNotFoundError: No module named 'contour_engine'` при запуске `run_worker.bat` на вычислительных узлах кластера.
  - **Устранение 32-битного переполнения Qt (`'qint64'`):** сигналы `progress_signal` и `finished_signal` в `ZipPackageThread` переведены на 64-битные целые числа. Устранены отрицательные значения байтов и поломка расчета оставшегося времени (ETA), а также ошибка отображения размера архива (4.35 ГБ отображались как 57.1 МБ).
  - **Фоновый режим и кнопка сворачивания в `PackageProgressDialog`:** добавлен флаг `WindowMinimizeButtonHint` и кнопка «Фоном (свернуть)» в окно прогресса архивации. Диалог можно свернуть в панель задач как при создании воркера, так и при экспорте преднастроенного клиента. По завершении диалог автоматически активируется и оповещает пользователя.
  - **Настоящий автономный Portable Python (запуск в 1 клик без установки Python):** вместо непереносимой заглушки `venv` пакет воркера теперь включает реальный интерпретатор CPython 3.11, системные библиотеки (`DLLs/`, `Lib/`) и отфильтрованные пакеты ИИ (`site-packages`), что позволяет запускать `run_worker.bat` на любом чистом ПК без установки Python.
  - **Устранение ошибок распаковки («Отказано в доступе» в 7-Zip):** в архив добавлены явные записи каталогов для исключения race-condition в многопоточных распаковщиках; файлы упаковываются с сохранением Windows-атрибутов через `ZipInfo.from_file` без избыточного `force_zip64`; из `venv` исключены десятки тысяч лишних файлов тестов и примеров.
  - **Исправление системного PATH в bat-файлах:** в начало `run_worker.bat` и `setup_worker.bat` добавлена инициализация `set "PATH=%SystemRoot%\System32;%SystemRoot%;%PATH%"`, устраняющая ошибку `"chcp" не является внутренней или внешней командой`.
- **Асинхронная фоновая загрузка DICOM во вьюер (устранение зависания заставки и интерфейса):**
  - Чтение сотен DICOM-файлов серии, извлечение пиксельных массивов и сборка 3D NumPy объема перенесены в отдельный фоновый поток `ViewerLoadWorker (QThread)` в `server_app.py` и `client_app.py`.
  - Устранена 5–10 секундная блокировка главного потока GUI и очереди событий Qt при запуске программы и выборе пациента.
  - Заставка (Splash Screen) теперь закрывается мгновенно (`self.hide()`, `self.close()`) сразу после отображения главного окна без многосекундного зависания с надписью «Готов к работе!».
- **Надежное сохранение настроек и стратегии очереди кластера:**
  - Добавлено сохранение параметра `dispatch_policy` в `save_settings()` и гарантированный сброс всех настроек на диск через `self.settings.sync()` в конце метода.
  - Вкладка `⚡ Кластер` при инициализации восстанавливает сохраненную стратегию распределения из `server_settings.ini`.
  - Смена стратегии в комбобоксе интерфейса сервера теперь на лету синхронизируется с запущенным подпроцессом FastAPI через REST API (`POST /api/cluster/policy`), а статус узлов считывается через `GET /api/cluster/status`.
- **Плавный старт интерфейса:**
  - Первичное автосканирование рабочей директории при старте сервера и клиента переведено в тихий фоновый режим (`is_manual=False`), устраняя блокировку окна модальным окном прогресса `QProgressDialog` и деактивацию элементов управления.

### Added
- **Интерактивный диалог создания пакетов с прогресс-баром (`PackageProgressDialog`):**
  - Фоновый потоковый архиватор `ZipPackageThread (QThread)` с блочной записью (по 2 МБ) в формате ZIP64.
  - Современное темное диалоговое окно прогресса с живым отображением процентов (0–100%), упакованных и общих мегабайт/гигабайт, текущего имени файла, скорости сжатия (МБ/с) и расчетного оставшегося времени (ETA).
  - Поддержка отмены операции в 1 клик с безопасной очисткой незавершенного архива без зависания интерфейса.
  - Применяется как при сборке автономных воркеров, так и при экспорте преднастроенного клиента `ASS_Client_Configured.zip`.
- **Автономные оффлайн-пакеты вычислительных узлов (Worker Deployment Package):**
  - Возможность включения в пакет воркера готового окружения Python + PyTorch (`venv/`, ~5.7 ГБ) и локального кэша весов нейросетей TotalSegmentator (`totalseg_home/`, ~1.3 ГБ).
  - Скрипт `run_worker.bat` автоматически активирует локальные переменные `TOTALSEG_HOME_DIR` и `TOTALSEG_WEIGHTS_PATH`, позволяя воркеру мгновенно начать оконтуривание без установки Python и без доступа в сеть интернет.
  - Чекбоксы выбора состава пакета и опция «Быстрое сжатие» (уровень 1) в диалоге `CreateWorkerDialog`.

### Added
- **Локальный центр обновлений (Centralized Auto-Update Hub):**
  - Серверный репозиторий бинарных обновлений (`updates/client/` с метаданными `version.json`).
  - REST API эндпоинты `/api/updates/client/info`, `/api/updates/client/download` и `/api/updates/client/upload`.
  - Фоновый загрузчик клиента (`ClientUpdater`), скачивающий обновление без зависания интерфейса и без прерывания работы врача.
  - Ненавязчивая зеленая кнопка `🔄 Обновить (vX.Y.Z)` в заголовке окна клиента; самообновление исполняемого файла «на лету» через `updater.bat` с перезапуском и сохранением конфигурации.
  - Административный интерфейс в окне сервера для загрузки свежих дистрибутивов `ASS_Client.exe` для раздачи по закрытой больничной сети.
- **Zero-Configuration Deployment и UDP Auto-Discovery:**
  - UDP Broadcast сервис автоматического обнаружения серверов ASS в локальной сети клиники (`src/network/discovery.py`, порт 8001).
  - Клиент при первом старте или смене IP автоматически находит Master-сервер и подставляет его сетевой адрес.
  - Интерактивный диалог `ServerAddressDialog` на клиенте с кнопкой `🔍 Автопоиск` по клику на индикатор статуса сервера.
  - Экспорт преднастроенного архива клиента (`ASS_Client_Configured.zip`) в 1 клик из настроек сервера для развертывания на новом ПК за 30 секунд.
- **Кластер вычислений (Multi-Worker Compute Pool & Load Balancer):**
  - Распределение ресурсоемких расчетов TotalSegmentator на CPU по пулу рабочих станций с 16 ГБ ОЗУ.
  - Архитектура Master-Worker с динамической регистрацией узлов и watchdog-мониторингом через Heartbeat (порт 8000).
  - Три настраиваемые стратегии балансировки нагрузки: «Приоритет воркеров» (`offload_workers`, по умолчанию), «Выделенный координатор» (`dedicated_coordinator`), «Первый свободный узел» (`first_available`).
  - Гарантия врачебной тайны и соблюдение 152-ФЗ / HIPAA: вычислительные воркеры мгновенно и безвозвратно удаляют все файлы КТ и промежуточные маски сразу после формирования RTSTRUCT.
  - Новая графическая вкладка `⚡ Кластер` на сервере: отображение сводки памяти, состояния узлов (🟢 Свободен / 🔵 Расчет / ⚪ Офлайн), текущего пациента, загрузки CPU/ОЗУ.
  - **Генератор пакетов вычислительных узлов (Worker Deployment Package):**
    - Кнопка `➕ Создать узел воркера...` в окне кластера и настройках сервера.
    - Автоматический опрос зарегистрированных узлов с инкрементом номеров (`Worker-01`, `Worker-02`...) и генерацией уникального ID (`worker_XX_<uuid>`).
    - Экспорт готового ZIP-дистрибутива с преднастроенным `server_settings.ini` (прописан IP сервера и имя узла), скриптами запуска `run_worker.bat`, автонастройки `setup_worker.bat` и `README_WORKER.txt`.
    - Реестр созданных воркеров `config/registered_workers.json`.
  - **Компиляция клиента «на лету» из GUI сервера:**
    - Расширенная кнопка экспорта клиента с диалогом выбора: «🚀 Скомпилировать свежий клиент и упаковать» (запуск PyInstaller в `QThread` с живым логом и индикатором) либо «⚡ Быстрый экспорт».
    - Автоматическая регистрация свежесобранного EXE в сервере с обновлением раздаваемой версии и сохранением в преднастроенный ZIP `ASS_Client_Configured_<IP>.zip`.
- **Руководство системного администратора (`docs/ADMIN_GUIDE.md`):**
  - Исчерпывающая документация по сетевым портам, Windows Firewall, архитектуре Master-Worker, Zero-Config и обновлению без интернета.
- **Единая очередь на клиенте:** клиент отображает полный список задач с сервера; задачи текущего клиента визуально выделяются (`[Этот ПК]`), чужие задачи защищены от отмены и модификации (режим «только чтение»).
- **Мгновенное сохранение IP и удобная настройка:** поле адреса сервера моментально синхронизируется в обычный текстовый файл `config/client_settings.ini`; добавлен быстрый диалог настройки сетевого IP по клику на индикатор статуса сервера.
- **Поддержка кастомной папки `temp_dir`:** возможность выноса промежуточной обработки КТ и архивов на выделенный диск или RAM-диск (например, `R:\temp`) на сервере и клиенте.
- **Корректная классификация `body` в DICOM RTSTRUCT:** теги `RTROIInterpretedType = "BODY"` и `ROIObservationDescription = "Type:Body,..."` для корректного отображения тела как Body (а не OAR/External) на станциях планирования Monaco, Eclipse и др.
- Модульные тесты `tests/test_body_structure_type.py` для валидации генерации RTSTRUCT и конфигурации путей.
- Модульные тесты `tests/test_ui_and_elekta_filter.py` для тестирования сетевого фильтра сокетов и ассетов.
- Базовая документация: [ROADMAP.md](.agent/docs/ROADMAP.md), [ARCHIVE.md](.agent/docs/ARCHIVE.md), [IMPLEMENTATION_PLAN.md](.agent/docs/IMPLEMENTATION_PLAN.md).
- **Кастомизация имен структур RTStruct (`config/structure_names.json`):** выделенный конфигурационный файл для настройки имен структур, попадающих в итоговый DICOM RTSTRUCT (с сохранением базовых наименований интерфейса и кастомных имен в скобках). Автоматически заполнен актуальными названиями для всех 434 поддерживаемых структур.
- **Контекстное меню переименования структур в RTStruct (ПКМ):** в интерфейсе сервера по правому клику мыши на любую структуру в дереве органов открывается диалог `✏️ Переименовать структуру в RTStruct`, позволяющий администратору сервера мгновенно изменить имя структуры для RTSTRUCT с сохранением в конфигурации.
- **Синхронизация имен структур между сервером и клиентом:** клиент автоматически загружает актуальные имена структур с сервера через `/api/config` и отображает обновленные имена в скобках.
- Модульные тесты `tests/test_structure_names.py` для валидации 434 структур, методов движка `get_rtstruct_name` и API эндпоинта `POST /api/config/structure_names`.
- **Сплэш-скрин загрузки:** премиальный экран загрузки (`src/ui/splash.py`) со шкалой прогресса и отображением этапов запуска для клиента и сервера.
- **Интерактивная валидация портов в Elekta mod:** автоматическая проверка занятости локального порта (`bind`) с подсветкой поля красной рамкой и подробной подсказкой при конфликте с другим ПО.
- **Фильтрация шума pynetdicom:** перехват разрыва сокетов Monaco (`WinError 10054`) в `elekta_mod.py` без падения и лишних трейсбеков в консоли.
- **Цитирование и атрибуция TotalSegmentator в README.md:** добавлен раздел с описанием открытой модели TotalSegmentator (Department of Research and Analysis, University Hospital Basel), ссылкой на репозиторий и полной библиографической ссылкой на публикацию авторов (Wasserthal et al., 2023, Radiology: AI).
- **Контекстное меню «📂 Открыть папку в Проводнике»:** добавлено действие ПКМ в таблицу серий на клиенте и сервере для быстрого перехода к папке пациента.

### Changed
- **Ребрендинг и заголовки:** заголовки окон стандартизированы до `Auto Segmentation System [Сервер]` и `Auto Segmentation System [Клиент]`, обновлены `AppUserModelID` (`ASS.Server.1.0` и `ASS.Client.1.0`).
- **Раздельные премиальные иконки:** внедрены индивидуальные наборы иконок высокого разрешения и мультиразмерные `.ico` для сервера (`icon_server.ico/png`) и клиента (`icon_client.ico/png`).
- **Надежное запоминание устройства (GPU/CPU):** выбор сохраняется в `server_settings.ini` и `client_settings.ini`, предотвращен сброс состояния при перезапуске, выбор клиента корректно учитывается сервером.
- **Таблица очереди:** ширина колонки «Клиент» увеличена в 2 раза (до 200 px) для полного отображения имени ПК и бейджа `(Этот ПК)`.
- **Автопрокрутка лога:** окно лога гарантированно смещается к последним строкам по окончании расчетов.
- **Очистка логов:** удалены избыточные отладочные записи `[Elekta Debug]: ...`.
- **Централизация выбора вычислительного устройства (GPU/CPU) на сервере:** из интерфейса клиента удалён лишний блок переключения «Вычислительное устройство», клиент больше не передает серверу принудительный выбор устройства.
