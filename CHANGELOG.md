## [2.0.42] - 2026-10-30
- **Стабилизация расчёта оставшегося времени (ETA) и монотонный прогресс многозадачной сегментации:**
  - В [contour_engine.py](file:///d:/ASS/contour_engine.py) реализовано пропорциональное разбиение диапазона прогресса инференса ИИ (10%–88%) между задачами TotalSegmentator для пресетов, требующих нескольких моделей (например, `total` и `heartchambers_highres` для пресета `thorax`). Введён барьер монотонности `max_reported_progress`, исключающий скачки прогресса назад при переходе ко второй модели или скачивании весов.
  - В [server/queue_manager.py](file:///d:/ASS/server/queue_manager.py) добавлен метод `update_progress_and_eta` с экспоненциальным сглаживанием (EMA, $\alpha = 0.15$), фильтрацией нестабильных ранних значений (прогресс $< 8\%$) и ограничением резких скачков вверх (не более $\times 1.25$).
  - Реализован метод `get_effective_elapsed_and_eta`, обеспечивающий живой отсчёт прошедшего времени и плавное посекундное убывание ETA между поступлениями stdout из подпроцесса.
  - В [server/server_api.py](file:///d:/ASS/server/server_api.py) эндпоинт статуса задачи переведён на `get_effective_elapsed_and_eta()`.
  - Добавлены модульные тесты в [tests/test_eta_and_progress.py](file:///d:/ASS/tests/test_eta_and_progress.py).
- **Исправление сопоставления ROI (Fuzzy Matching) и устранение ложного импорта OAR:**
  - В словарь псевдонимов [config.py](file:///d:/ASS/config.py) (`EXTERNAL_ALIASES`) добавлены алиасы для внешнего контура тела (`bodyskin`, `skinbody`, `bodyexternal`), верхней полой вены (`venacavasup`, `venacavasuperior`, `svc`) и нижней полой вены (`inferiorvenacava`, `venacavainf`, `venacavainferior`, `ivc`).
  - В [client_app.py](file:///d:/ASS/client_app.py) и [server_app.py](file:///d:/ASS/server_app.py) нормализованный словарь распознавания OAR (`supported_norm_map`) дополнен именами из [config/structure_names.json](file:///d:/ASS/config/structure_names.json) (`get_rtstruct_name`), благодаря чему сгенерированные RTSTRUCT структуры (включая `Body / Skin` и `Vena Cava Sup`) корректно распределяются по стандартным анатомическим группам («Внешний контур тела», «Грудная клетка») и больше не попадают ошибочно в блок «ИМПОРТИРОВАННЫЕ OAR».
  - Добавлены модульные тесты `test_rtstruct_fuzzy_mapping` в [tests/test_structure_names.py](file:///d:/ASS/tests/test_structure_names.py).

## [2.0.41] - 2026-10-29
- **Кнопка быстрого перезапуска сервера с защитой от случайного нажатия:**
  - В панели управления сервером ([server_app.py](file:///d:/ASS/server_app.py)) рядом со статусом «СЕРВЕР АКТИВЕН» добавлена кнопка **«🔄 Перезапуск»**.
  - Реализован двойной контур защиты от случайного нажатия: при клике мышью требуется удержание клавиши **Ctrl** (иначе выводится предупреждающая подсказка).
  - Для работы без мыши назначены горячие клавиши **Ctrl+Shift+R** (и **Ctrl+Alt+R**).
  - Предусмотрена проверка активных расчётов: при наличии задачи со статусом `PROCESSING` запрашивается подтверждение перед прерыванием операции.
  - При перезапуске настройки автоматически сохраняются, фоновый сервис FastAPI завершается с освобождением порта 8000, и поднимается новый процесс приложения.

  - В таблицу «Очередь автооконтурирования (на сервере)» в [server_app.py](file:///d:/ASS/server_app.py) и [client_app.py](file:///d:/ASS/client_app.py) добавлена новая колонка **«Время»** между «Прогресс» и «Получено».
  - В процессе сегментации (`PROCESSING`) отображается живой таймер с синей индикацией `⏳ mm:ss`, а по завершении (`SUCCESS` / `FAILED`) — точное итоговое время расчета (например, `02:35` с зеленой подсветкой при успешном выполнении). Для задач в ожидании (`PENDING`) отображается прочерк `—`.
  - Версия системы повышена до `2.0.41`, собран актуальный дистрибутив `ASS_Client_PyQt6.exe` для удалённого обновления клиентских рабочих мест.

  - В диалоге «👥 Подключенные клиенты и блокировка» ([server_app.py](file:///d:/ASS/server_app.py)) внедрена проверка версии клиента относительно актуальной версии сервера: для клиентов с актуальной версией (`ver >= actual_ver`) кнопка действия становится приглушенной серой (`#2b2b30`, текст `#888888`) с надписью `✓ Актуален` и отключается (`setEnabled(False)`), исключая случайные повторные обновления. Яркая синяя кнопка `🔄 Обновить клиент` отображается только для клиентов, требующих обновления.
  - В окне «📦 Управление моделями ИИ TotalSegmentator» ([server_app.py](file:///d:/ASS/server_app.py) и [client_app.py](file:///d:/ASS/client_app.py)) исправлено ложное предупреждение `🔑 (Нужна лицензия)`: добавлена динамическая проверка активного лицензионного ключа. При наличии активной лицензии выводится `🔑 (Лицензия активна ✓)`, а предупреждение о необходимости лицензии отображается только при её отсутствии.

- **Бесшовное обновление клиента по архитектуре DICOM_WatchDog и монотонный прогресс сборки:**
  - Устранено появление черного окна с заголовком `"find 12948"` и мертвое зависание процесса обновления на клиенте: ненадежный цикл ожидания `tasklist | find` в батнике полностью заменен на проверенную Windows in-place rename архитектуру (адаптированную из [DICOM_WatchDog](https://github.com/Flacozyabra/DICOM_WatchDog)).
  - Процесс обновления теперь выполняется на лету: работающий файл `ASS_Client.exe` переименовывается в `_old_ASS_Client.exe` средствами Windows NTFS (разрешено ОС), а новый скачанный бинарник немедленно перемещается на целевое место. Запускается легковесный независимый сценарий `_restart_update_{pid}.bat` с очищенным окружением `get_clean_env()` (без `_MEIPASS`, `PYTHONPATH`, `PYTHONHOME`), который после 2-секундной задержки запускает новую версию через `start "" "{target}"` и самоудаляется.
  - Добавлена функция `cleanup_old_exe()`, которая автоматически удаляет остаточные файлы `_old_*.exe` при каждом старте клиента (в точке входа `__main__` и при инициализации `MainWindow`).
  - Исправлен парсер прогресса компиляции клиента на сервере (`server/server_api.py`): устранено ложное срабатывание на вывод `Processing ...` команды `pip install pyinstaller` (из-за которого прогресс-бар сразу перескакивал на 75% «Сборка DLL»). Введена строгая монотонность процентов и контекстная проверка этапов PyInstaller (`current_percent >= 45`, `50`, `60`, `70`).
  - Устранено зависание статуса «⏳ Отправка...» в таблице клиентов на сервере: в `BlacklistManager.get_clients_info()` добавлен 45-секундный таймаут на снятие зависших задач при падении или недоступности клиента, а также моментальный сброс очереди обновления при первом же heartbeat клиента с новой версией.
