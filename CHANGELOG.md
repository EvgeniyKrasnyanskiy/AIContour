# Changelog

Все заметные изменения в проекте ASS (Auto Segmentation System) фиксируются в данном файле.
Формат соответствует [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).

## [Unreleased]
### Added
- **Локальный центр обновлений (Centralized Auto-Update Hub):**
  - Серверный репозиторий бинарных обновлений (`updates/client/` с метаданными `version.json`).
  - REST API эндпоинты `/api/updates/client/info`, `/api/updates/client/download` и `/api/updates/client/upload`.
  - Фоновый загрузчик клиента (`ClientUpdater`), скачивающий обновление без зависания интерфейса и без прерывания работы врача.
  - Ненавязчивая зеленая кнопка `🔄 Обновить (vX.Y.Z)` в заголовке окна клиента; самообновление исполняемого файла «на лету» через `updater.bat` с перезапуском и сохранением конфигурации.
  - Административный интерфейс в окне сервера для загрузки свежих дистрибутивов `ASS_Client.exe` для раздачи по закрытой больничной сети.
- **Zero-Configuration Deployment и UDP Auto-Discovery:**
  - UDP Broadcast сервис автоматического обнаружения серверов ASS в локальной сети клиники (`src/network/discovery.py`, порт 8001).
  - Клиент при первом старте или смене IP автоматически находит Master-сервер и подставляет его сетевой адрес.
  - Интерактивный диалог `ServerAddressDialog` на клиенте с кнопкой `🔍 Автопоиск` по клику на индикатор статуса сервера.
  - Экспорт преднастроенного архива клиента (`ASS_Client_Configured.zip`) в 1 клик из настроек сервера для развертывания на новом ПК за 30 секунд.
- **Кластер вычислений (Multi-Worker Compute Pool & Load Balancer):**
  - Распределение ресурсоемких расчетов TotalSegmentator на CPU по пулу рабочих станций с 16 ГБ ОЗУ.
  - Архитектура Master-Worker с динамической регистрацией узлов и watchdog-мониторингом через Heartbeat (порт 8000).
  - Три настраиваемые стратегии балансировки нагрузки: «Приоритет воркеров» (`offload_workers`, по умолчанию), «Выделенный координатор» (`dedicated_coordinator`), «Первый свободный узел» (`first_available`).
  - Гарантия врачебной тайны и соблюдение 152-ФЗ / HIPAA: вычислительные воркеры мгновенно и безвозвратно удаляют все файлы КТ и промежуточные маски сразу после формирования RTSTRUCT.
  - Новая графическая вкладка `⚡ Кластер` на сервере: отображение сводки памяти, состояния узлов (🟢 Свободен / 🔵 Расчет / ⚪ Офлайн), текущего пациента, загрузки CPU/ОЗУ.
- **Руководство системного администратора (`docs/ADMIN_GUIDE.md`):**
  - Исчерпывающая документация по сетевым портам, Windows Firewall, архитектуре Master-Worker, Zero-Config и обновлению без интернета.
- **Единая очередь на клиенте:** клиент отображает полный список задач с сервера; задачи текущего клиента визуально выделяются (`[Этот ПК]`), чужие задачи защищены от отмены и модификации (режим «только чтение»).
- **Мгновенное сохранение IP и удобная настройка:** поле адреса сервера моментально синхронизируется в обычный текстовый файл `config/client_settings.ini`; добавлен быстрый диалог настройки сетевого IP по клику на индикатор статуса сервера.
- **Поддержка кастомной папки `temp_dir`:** возможность выноса промежуточной обработки КТ и архивов на выделенный диск или RAM-диск (например, `R:\temp`) на сервере и клиенте.
- **Корректная классификация `body` в DICOM RTSTRUCT:** теги `RTROIInterpretedType = "BODY"` и `ROIObservationDescription = "Type:Body,..."` для корректного отображения тела как Body (а не OAR/External) на станциях планирования Monaco, Eclipse и др.
- Модульные тесты `tests/test_body_structure_type.py` для валидации генерации RTSTRUCT и конфигурации путей.
- Модульные тесты `tests/test_ui_and_elekta_filter.py` для тестирования сетевого фильтра сокетов и ассетов.
- Базовая документация: [ROADMAP.md](.agent/docs/ROADMAP.md), [ARCHIVE.md](.agent/docs/ARCHIVE.md), [IMPLEMENTATION_PLAN.md](.agent/docs/IMPLEMENTATION_PLAN.md).
- **Кастомизация имен структур RTStruct (`config/structure_names.json`):** выделенный конфигурационный файл для настройки имен структур, попадающих в итоговый DICOM RTSTRUCT (с сохранением базовых наименований интерфейса и кастомных имен в скобках). Автоматически заполнен актуальными названиями для всех 434 поддерживаемых структур.
- **Контекстное меню переименования структур в RTStruct (ПКМ):** в интерфейсе сервера по правому клику мыши на любую структуру в дереве органов открывается диалог `✏️ Переименовать структуру в RTStruct`, позволяющий администратору сервера мгновенно изменить имя структуры для RTSTRUCT с сохранением в конфигурации.
- **Синхронизация имен структур между сервером и клиентом:** клиент автоматически загружает актуальные имена структур с сервера через `/api/config` и отображает обновленные имена в скобках.
- Модульные тесты `tests/test_structure_names.py` для валидации 434 структур, методов движка `get_rtstruct_name` и API эндпоинта `POST /api/config/structure_names`.
- **Сплэш-скрин загрузки:** премиальный экран загрузки (`src/ui/splash.py`) со шкалой прогресса и отображением этапов запуска для клиента и сервера.
- **Интерактивная валидация портов в Elekta mod:** автоматическая проверка занятости локального порта (`bind`) с подсветкой поля красной рамкой и подробной подсказкой при конфликте с другим ПО.
- **Фильтрация шума pynetdicom:** перехват разрыва сокетов Monaco (`WinError 10054`) в `elekta_mod.py` без падения и лишних трейсбеков в консоли.
- **Цитирование и атрибуция TotalSegmentator в README.md:** добавлен раздел с описанием открытой модели TotalSegmentator (Department of Research and Analysis, University Hospital Basel), ссылкой на репозиторий и полной библиографической ссылкой на публикацию авторов (Wasserthal et al., 2023, Radiology: AI).
- **Контекстное меню «📂 Открыть папку в Проводнике»:** добавлено действие ПКМ в таблицу серий на клиенте и сервере для быстрого перехода к папке пациента.

### Changed
- **Ребрендинг и заголовки:** заголовки окон стандартизированы до `Auto Segmentation System [Сервер]` и `Auto Segmentation System [Клиент]`, обновлены `AppUserModelID` (`ASS.Server.1.0` и `ASS.Client.1.0`).
- **Раздельные премиальные иконки:** внедрены индивидуальные наборы иконок высокого разрешения и мультиразмерные `.ico` для сервера (`icon_server.ico/png`) и клиента (`icon_client.ico/png`).
- **Надежное запоминание устройства (GPU/CPU):** выбор сохраняется в `server_settings.ini` и `client_settings.ini`, предотвращен сброс состояния при перезапуске, выбор клиента корректно учитывается сервером.
- **Таблица очереди:** ширина колонки «Клиент» увеличена в 2 раза (до 200 px) для полного отображения имени ПК и бейджа `(Этот ПК)`.
- **Автопрокрутка лога:** окно лога гарантированно смещается к последним строкам по окончании расчетов.
- **Очистка логов:** удалены избыточные отладочные записи `[Elekta Debug]: ...`.
- **Централизация выбора вычислительного устройства (GPU/CPU) на сервере:** из интерфейса клиента удалён лишний блок переключения «Вычислительное устройство», клиент больше не передает серверу принудительный выбор устройства. Сервер всегда автономно использует аппаратную конфигурацию (GPU/CPU и индекс видеокарты), заданную в настройках сервера.
- **Скрипты сборки клиента:** исправлен импорт PyInstaller в `build_clientPyQT5.py` и `build_clientPyQT6.py`, добавлены новые иконки клиента в сборку `ASS_Client.exe`, отключено создание избыточного ZIP-архива (в `dist/` создается только чистый автономный `ASS_Client.exe`).
- **Завершение полного ребрендинга (AIC / AI Contour -> ASS):** обновлены URL автообновлений с GitHub (`.../ASS/releases/latest`), DICOM AE Titles по умолчанию (`ASS_SCP`, `ASS_TEST_SCU`), заголовки диалоговых окон, тексты справки, сообщения API сервера и скрипты запуска `.bat`.

### Fixed
- **Отслеживание прогресса и загрузка весов нейросети:** в `contour_engine.py` разделены состояния скачивания моделей (`Downloading model...`) и инференса нейросети (`Predicting...`). Устранено ложное увеличение индекса цикла расчета при смене скачиваемых файлов, предотвращен перегруз логов и статусной строки `current_step` тысячами строк спама `tqdm`. Расчет процентов и ETA теперь рассчитываются строго по шагам сегментации.
- **Исключение невалидной CLI-задачи `total_v1`:** из маппинга задач и списка разрешенных органов исключена устаревшая задача `total_v1`, приводившая к сбою CLI TotalSegmentator v2 при наличии органа `pulmonary_artery` (маппинг перенаправлен на `heartchambers_highres`).
- **Устранение зависания при двойном клике по пациенту:** в таблице серий включен `NoEditTriggers` для предотвращения случайного входа в инлайн-редактирование ячеек; добавлен кэш `current_dicom_dir` для исключения повторного синхронного чтения сотен DICOM-файлов с диска при повторных кликах; запуск системного проводника `os.startfile` переведён в фоновый поток без блокировки основного UI.
- **Отображение пациента во встроенном DICOM-вьере:**
  - Исправлена ошибка в `update_viewer_with_dicom` и удалении структур, возникавшая из-за `glob.glob()`. При наличии в имени папки пациента квадратных скобок (например, `Фамилия Имя [ID]`) модуль `glob` парсил скобки как шаблон регулярных выражений, возвращая пустой список файлов и оставляя экран вьюера черным. Поиск заменен на надежный листинг через `os.listdir` с поддержкой всех DICOM-срезов.
  - Добавлен автоматический выбор первого пациента в таблице при завершении сканирования папки DICOM (`on_scan_completed`), если серия не была выбрана ранее.
  - Подключен обработчик `cellClicked` для таблицы серий, позволяющий загружать срез даже при повторном клике по уже активной строке.
  - Добавлен переход на центральный срез объема (`mid_idx = len(slices) // 2`) и вызовы `autoLevels()` / `autoRange()` при загрузке 3D-томограммы, благодаря чему анатомия пациента сразу видна в окне мягких тканей вместо черного краевого среза вне тела.
- **Белый фон во время сплэш-скрина:** устранено преждевременное отображение и развертывание главного окна (`showMaximized`) во время работы сплэш-скрина; на мониторе отображается только аккуратная компактная карточка сплэш-скрина, а само главное окно открывается максимизированным точно в момент полного завершения инициализации.
- **Предупреждение pydicom write_like_original:** в `elekta_mod.py` устаревший параметр `write_like_original` заменен на современный `enforce_file_format=True`, что устранило предупреждения deprecation в логах при приеме DICOM-серий от Monaco TPS.
- **Диагностика и линтинг (Undefined Symbols & Signature Mismatch):** устранены ошибки статического анализатора IDE — добавлены недостающие импорты `get_version` в [server_app.py](file:///d:/ASS/server_app.py), `json` в [queue_manager.py](file:///d:/ASS/server/queue_manager.py) и `psutil` в [server_api.py](file:///d:/ASS/server/server_api.py); в [worker_service.py](file:///d:/ASS/server/worker_service.py) скорректированы имена аргументов вызова `ContourEngine.run_pipeline` (`remove_blobs`, `use_gpu`, `is_cancelled_cb`, `register_process_cb`).
