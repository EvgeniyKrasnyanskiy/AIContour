# Архив выполненных задач проекта ASS

В этом файле сохраняется история завершенных этапов, архитектурных доработок и фиксов.

---

## 2026-10-27: Кластер вычислений (Multi-Worker Pool), Portable Python и удаленное управление
- [Completed] **Автономный Portable Python для воркеров:** интеграция реального рантайма CPython 3.11, системных библиотек (`DLLs/`, `Lib/`) и отфильтрованных ИИ-пакетов (`site-packages`), обеспечивающая работу воркеров на чистых ПК без предварительной установки Python.
- [Completed] **Устранение ошибок распаковки и запуска воркера:**
  - Включение модулей движка (`contour_engine.py`, `config.py`, `version.txt`) в корень архива воркера.
  - Исправление исключений в `ZipPackageThread` (замена проверки подстроки `ex in d` на строгое сопоставление `d == ex`), предотвратившая случайное вырезание стандартных библиотек (`unittest`, `doctest`) и подмодулей (`pydicom.examples`, `torch`).
- [Completed] **Потокобезопасное автообновление таблицы кластера:** реализация `ClusterStatusSignaler(QObject)` взамен неработающего `QTimer.singleShot` из фонового потока. Автоматический опрос ограничен активной вкладкой «⚡ Кластер» (0 байт трафика на других вкладках).
- [Completed] **Удаленное включение и отключение воркеров (1-click Toggle):** добавлен эндпоинт `POST /api/cluster/worker/toggle` и 8-я колонка «Управление» в таблицу кластера сервера. Администратор может в 1 клик временно исключать воркер из пула задач (`⏸️ Отключить` / `DISABLED`) и возвращать его в работу (`▶️ Включить`).
- [Completed] **Скрытый запуск, проверка статуса и автозагрузка воркера:** добавлены скрипты `run_worker_no_console.bat` (запуск в фоне через `pythonw.exe`), `status_worker.bat` (проверка активности процесса и чтение логов в 1 клик), `stop_worker.bat` (остановка службы в 1 клик), `add_to_startup.bat` (добавление ярлыка в Windows Startup) и `remove_from_startup.bat` (удаление по маске). Все bat-скрипты переведены на чистый ASCII для исключения сбоев разбора кириллицы в Windows `cmd.exe`.

- [Completed] **Ребрендинг в ASS (Auto Segmentation System):** заменены заголовки окон, идентификаторы процессов Windows (`ASS.AutoSegmentationSystem.1.0`), мьютексы (`ASSClientMutex_1.0`, `ASSServerMutex_1.0`), скрипты сборки `ASS_Client.exe` / `ASS_Client_Portable.zip`, дефолтные DICOM AE Titles (`ASS_SCP`, `ASS_SCU`).
- [Completed] **Сетевая стабильность клиента:** подключено моментальное сохранение IP-адреса в `config/client_settings.ini` при вводе; добавлен быстрый диалог смены IP по клику на статус-индикатор сервера.
- [Completed] **Единая очередь (Read-Only для чужих задач):** клиентская таблица синхронизирована с очередью сервера; задачи оператора выделяются cyan-цветом и меткой `[Этот ПК]`; для чужих задач отмена заблокирована.
- [Completed] **Классификация контура `body`:** в RTSTRUCT для `body` проставляются теги `RTROIInterpretedType = "BODY"` и `ROIObservationDescription = "Type:Body,..."` для корректной классификации в Monaco/Eclipse.
- [Completed] **Новая иконка ASS:** сгенерирована и интегрирована новая неоновая иконка приложения (вид полушарий головного мозга сверху с аллюзией на аббревиатуру ASS). Файлы `app_icon.png` and `app_icon.ico` обновлены.
- [Completed] **Сборка переносимого клиента:** успешная компиляция `ASS_Client.exe` и формирование портативного дистрибутива `dist/ASS_Client_Portable.zip` (103.16 МБ) с включенным `config/client_settings.ini`.

## 2026-10-28: Полномасштабный запуск кластера вычислений, Portable Python и устранение конфликтов портов
- [Completed] **Устранение зависания задач в очереди:** исправлена кодировка файла `config/server_settings.ini` с поврежденного UTF-16 (с BOM) на корректный UTF-8.
- [Completed] **Смена политики нагрузки:** программная смена `dispatch_policy` на `offload_workers` и `first_available` через REST API, что позволило автоматически распределять задачи по свободным узлам кластера.
- [Completed] **Полная стабилизация и реальный инференс узла Worker-01:**
  - Успешное выполнение полного цикла расчета на удаленном CPU-узле: прием DICOM, конвертация в NIfTI, расчет нейросети TotalSegmentator nnUNet v2, постобработка, генерация валидного DICOM RTSTRUCT для TPS Monaco и обратная пересылка на Мастер.
  - Внедрена переменная окружения `ASS_CLUSTER_ROLE=worker` во все bat-скрипты воркера, исключающая случайный запуск узла в роли Мастера при перезаписи файлов конфигурации.
  - В батники воркера вшиты параметры адреса Мастера (`ASS_MASTER_URL`), имени узла и ID для автоматического восстановления связи при поврежденных или перезаписанных `.ini` файлах.
- [Completed] **Подсчет реально созданных структур из полученного RTSTRUCT:**
  - Устранена ошибка отображения «Добавлено структур: 0». Мастер-сервер в `QueueManager` теперь напрямую считывает реальное количество ROI из полученного от воркера файла RTSTRUCT (`StructureSetROISequence`) и корректно передает `Создано OAR: N` клиенту и в статистику.
- [Completed] **Защита жизненного цикла рабочих папок (`jobs/`):**
  - Добавлена гарантия создания `job_dir.mkdir(parents=True, exist_ok=True)` перед записью `result.zip`, устранившая ошибку `[Errno 2] No such file or directory` при долгом расчете задач на удаленных узлах.
- [Completed] **Автономный Portable Python и устранение конфликтов библиотек (Worker-02):**
  - Устранена ошибка `TypeError: dataclass() got an unexpected keyword argument 'slots'` при импорте Pydantic: в `PYTHONPATH` стандартная библиотека Python 3.11 (`venv\Lib`) теперь гарантированно ставится перед `site-packages`.
  - Удален устаревший сторонний бэкпорт `dataclasses==0.6` и `argparse==1.4.0` (предназначенные для Python 3.6/2.7), вызывавшие конфликт с нативными модулями Python 3.11. В запускающие bat-скрипты добавлено автоудаление устаревших файлов при старте, а в генератор пакетов `server_app.py` — правила исключения из архивации.
- [Completed] **Настраиваемый порт воркера (`ASS_WORKER_PORT`) и бесконфликтное сосуществование с MOSAIQ:**
  - Добавлена поддержка переменной окружения `ASS_WORKER_PORT` (и секции `[General] port` в `server_settings.ini`), позволяющая запускать воркер на порту 8005 (или любом другом).
  - Устранен сетевой конфликт `[Errno 10048] (WSAEADDRINUSE)` со службами планирующей станции Elekta MOSAIQ, использующими порт 8000 по умолчанию.
  - Порт воркера автоматически передается в регистрационном запросе на Мастер, обеспечивая корректную маршрутизацию задач и мониторинг в таблице кластера.
- [Completed] **Успешное развертывание пула кластера (160 ГБ ОЗУ):**
  - `Master (Локальный)` — `127.0.0.1:8000` (16 ГБ ОЗУ)
  - `Worker-01` — `192.168.5.196:8000` (16 ГБ ОЗУ)
  - `Worker-02` — `192.168.5.172:8005` (128 ГБ ОЗУ)
  - Все три узла активны, отслеживаются в реальном времени и готовы к параллельной обработке задач оконтуривания.
