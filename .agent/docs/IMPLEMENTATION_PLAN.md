## Этап 12: Кластер вычислений (Multi-Worker Pool & Load Balancer) [Completed]
- **Режимы запуска сервера (`server_app.py`):**
  - Поддержка ролей `Master (Главный сервер)` и `Worker (Вычислительный узел)`.
- **Динамический пул воркеров на Мастере (`server/cluster_manager.py`):**
  - Регистрация и Heartbeat воркеров (`/api/cluster/register`, `/api/cluster/heartbeat`).
  - Watchdog-мониторинг состояния узлов (🟢 Свободен / 🔵 Расчет / ⚪ Офлайн) с живым обновлением во вкладке `⚡ Кластер` GUI Сервера.
- **Политики распределения (Dispatch Policy):**
  - «Приоритет воркеров» (`offload_workers`, по умолчанию): Мастер держит CPU свободным для сети, отдавая КТ свободным воркерам; считает локально только при нехватке узлов.
  - «Выделенный координатор» (`dedicated_coordinator`): Мастер работает только как диспетчер.
  - «Первый свободный» (`first_available`): Задача отдается первому освободившемуся узлу.
- **Передача данных и жесткая зачистка КТ (`server/worker_service.py`):**
  - Передача архива КТ на узел через `/api/worker/execute`, возврат готового `result.zip` (`/api/worker/result/{id}`), гарантированное мгновенное удаление всех КТ-файлов на воркере сразу после отправки результата (`/api/worker/cleanup/{id}`).
